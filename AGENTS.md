# AGENTS.md — lego

*lego* (Latin: "I read") is a friendly reading interface for classical Latin text.
Readers view a passage (currently Vergil, **Aeneid Book 1**); hovering a word shows its
morphology — case, declension, tense, mood — at a selectable assistance level that never
reveals the English translation unless explicitly requested. Words that belong together
(adjective↔noun agreement, subject↔verb) highlight together, and sentences can be shown
in reading order.

Morphological analysis is powered by
[perseids-tools/morpheus](https://github.com/perseids-tools/morpheus) via the
[morpheus-api](https://github.com/perseids-tools/morpheus-api) HTTP wrapper.

## Architecture

```
docker-compose.yml        morpheus-api container → http://localhost:1315/latin/:word
packages/shared           data contract (types.ts) + Perseus-format parser (morpheus.ts)
packages/api              Fastify service :8787 → GET /latin/:word  (clean JSON + cache)
packages/corpus           import pipeline: TEI XML → tokens → precomputed analyses JSON
packages/web              React + Vite reader UI (fetches corpus JSON from public/corpus/)
texts/                    raw TEI text sources (committed)
packages/web/public/corpus/   generated passage JSON (committed, regenerated by import)
```

Runtime strategy: **precompute + live fallback**. Every token of the passage is analyzed
once at import time into static JSON (instant hovers, no backend needed to read). The
`packages/api` service stays available for ad-hoc lookup of arbitrary words.

## Commands

```sh
pnpm install
pnpm morpheus:up              # start morpheus container (docker compose)
pnpm import                   # rebuild corpus JSON from TEI (Aeneid 1)
pnpm dev                      # api (:8787) + web (:5173) in watch mode
pnpm test / pnpm typecheck / pnpm build
curl localhost:1315/latin/feminam    # raw morpheus-api output
curl localhost:8787/latin/feminam    # clean JSON from our wrapper
```

## Data contract

**Source of truth: `packages/shared/src/types.ts`.** Read it before touching anything.
Key shapes:

- `MorpheusAnalysis` — one parse of a form (pos, lemma, cases/numbers/genders arrays,
  tense/mood/voice/persons, degree, stem, features).
- `Token` — surface text, analysis form, verse line, punctuation, enclitic splits.
- `Sentence` — tokens + `groups` (words that highlight together) + `order` (reading-order chunks).
- `Passage` — metadata, sentences, and a form→analyses map shared across tokens.

**Never change the contract without updating all three packages and their tests.**
Packages import each other's source directly (`@lego/shared` resolves to `src/index.ts`);
no build step is needed in dev — use `tsx` / `vite` / `vitest`.

## Assistance levels (web)

| Level | Reveals |
|---|---|
| 1 | Part of speech only |
| 2 | Full morphology + lemma |
| 3 | Principal parts / declension pattern — no English |
| 4 | Click-to-reveal English gloss — **never displayed unrequested** |

Levels only *filter* what the analysis JSON already contains; the UI must not invent data.

## Conventions

- TypeScript strict mode; ESM everywhere; no default exports in shared.
- All new source files live under `packages/<pkg>/src/`; tests colocated as `*.test.ts`.
- Ambiguous forms keep **all** morpheus analyses (show-all, no ranking yet).
- Enclitics (`-que`, `-ve`, `-ne`) are split off the token before analysis.
- Latin text is stored without macrons (morpheus does not produce them).

## Subagents

Three build agents are defined for this repo. Spawn them for the phases below; they own
their packages and must keep `pnpm test` and `pnpm typecheck` green when they finish.

### 1. morpheus-setup

**Owns:** `docker-compose.yml`, `packages/shared`, `packages/api`.

- Implement `parseMorpheus()` in `packages/shared/src/morpheus.ts` to satisfy the
  contract and its doc comment: parse `<NL>…</NL>` Perseus-format records into
  `MorpheusAnalysis[]`; slash groups become arrays; map known endings to the enums
  (`masc nom sg`, `3rd sg pres ind act`, …); unknown tokens go to `features` verbatim.
- `packages/api`: Fastify service on :8787 with `GET /latin/:word` → `{ form, analyses }`
  using the shared parser, calling `http://localhost:1315/latin/:word?opts=S`
  (case-insensitive handling for capitalized words), with an in-memory cache.
- Verify against the live container (`curl localhost:1315/latin/feminam`) — do not trust
  README examples alone; test real output including ambiguous multi-analysis words
  (e.g. `amarat`? no — try `puella`, `amo`, `feminam`, `arma`, `virum`, `cano`).
- Unit tests for the parser (golden files under `packages/shared/test/`) and a route test.

### 2. corpus-import

**Owns:** `packages/corpus`, `texts/`, generated JSON in `packages/web/public/corpus/`.

- Acquire Vergil Aeneid Book 1 TEI XML from PerseusDL/canonical-latinlit (GitHub).
  Verify the exact file and its license; record name/url/license in `Passage.source`.
- Pipeline (`pnpm import`): parse TEI → passage model (line numbers preserved) →
  sentence segmentation → tokenization (split punctuation; split enclitics
  `-que`/`-ve`/`-ne`; lowercase forms) → analyze every distinct form via morpheus
  (container :1315 or api :8787, with on-disk caching so re-runs don't re-query) →
  agreement groups + reading-order chunks → write `aeneid-1.json` to
  `packages/web/public/corpus/`.
- Agreement heuristics: adjective/participle ↔ noun/pronoun matching case+number
  (and gender when unambiguous); subject ↔ finite verb matching person+number.
- Reading-order heuristics: chunk sentences around finite verbs and prepositional
  phrases; conjunctions split chunks. Mark heuristic output as overridable later.
- Word forms morpheus cannot parse: keep the token, record empty analyses (UI flags it).
- Commit raw TEI under `texts/` with a license note in `texts/README.md`.

### 3. frontend

**Owns:** `packages/web` (everything except `public/corpus/`).

- React 19 + Vite + TypeScript. Fetch `public/corpus/aeneid-1.json` at runtime.
  If the corpus JSON doesn't exist yet, create a small mock fixture
  (`src/fixtures/mock-passage.json`) matching the contract to develop against —
  never commit a fake into `public/corpus/`.
- Reader view: passage by verse line, clean typography, tokens as hoverable/focusable
  elements (keyboard accessible).
- Hover/tap popover: renders analyses filtered by the assistance-level control
  (slider or segmented control, persisted to localStorage). Level boundaries per the
  table above; ambiguous forms visibly marked (e.g. dotted underline) with all parses
  listed.
- Agreement highlighting: hover/select a word → its `groups` partners highlight softly.
- Reading-order view: toggle showing each sentence as numbered sense-unit chunks
  (from `Sentence.order`), interleaved or below the original.
- Level 4: per-word "reveal gloss" affordance only — English never appears otherwise.
- Component tests with vitest for popover rendering per level and group highlighting.
